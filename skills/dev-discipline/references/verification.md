# 验证链与完成判定

历史事故里最贵的一类错误不是"做错了"，而是"做对了但宣布完成时验证深度不够"：行数对账分毫不差，但下游看板整列消失；单测 80/80 全绿，SQL 语法错到真库才炸；审计转 PASS 当天宣布修复，三天后发现是假阴性。"完成"是一个可证明的状态，不是一个感觉。

## 完成判定顺序（按改动类型，缺一环不算完）

**后端代码**：静态检查（编译/类型）通过 → 重启生效或确认热重载真的加载了新代码（热重载会静默漏检，不可默认信任）→ 接口实测响应 shape（不是看日志，是 curl 真实端点）→ DB 实证数值 → 浏览器 0 console error。

**数据修复/回填**：终态行数用**全部处理完之后**的一次性 count 校验（逐表即时 count 会被后续步骤的级联副作用骗过）→ 与权威源对账 → **等数据真正流过一轮管道**（见下"假阴性"）。

**前端**：build 通过 → 部署生效从**浏览器侧**确认（fetch 版本接口 + 看 script hash），宿主侧文件校验只是必要条件。

**部署**：容器镜像 ID + 进程启动时间已刷新（文件新 ≠ serving 进程新）→ 健康探测过 → 盯启动日志到完成。

## 穿透原则：验证到真实出口

每一层都可能是最后一层验证，也都是下一层的谎言来源：

- raw SQL 聚合结果 ≠ API 输出（API 层还有过滤、映射、权限准入）——页面类修复的终判 = 在目标环境真调**页面同款函数**（同参）
- API 输出 ≠ 页面显示（前端还有自己的映射、常量、暗门条件）
- 源表行数对账 ≠ 下游看板显示（JOIN 链路上的外键元数据断链照样全零）
- `docker exec` 起新进程读到的文件 ≠ serving 进程内存里的代码（bind mount 必然是新文件）

**账户/实体合并类操作**的清点清单必须含档案行上的全部派生字段（归属、维度、来源标记），逐字段"转移 or 确认有班次自动回填"；完成判定 = 下游主看板真显示出数。

## 假阴性：当天转绿不算修复

补建档案/账号类修复，当天审计转 PASS 只说明"没数据可丢"，不说明"数据来了能匹配"。**完成判定 = 数据行真正流过管道一轮**（下一班之后 dropped/unmatched 清零）。修复验证窗口太短是经典假阴性来源。

同理，同一实体在多条管道可能有**不同匹配键**（external_id / UUID / 名字）——拿一条管道的 PASS 外推全部，是绿的掩盖红的。逐条管道独立验。

## 锚点对账法

改动前记录关键锚点数字（金额、行数、KPI 值、版本号），改动后逐一复核**分毫不差**：

- 对账输出精确到分（小数位），"大致相同"要追问差值来源；差值要能逐项分解闭合（口径差 X + 缺口 Y + 尾差 Z = 总差）
- 用户的业务常识是不变量的一环（如"总量 A 必大于分量 B"）——违反业务常识的系统数字，即使内部自洽也要查
- 供后续对比的基线数字**当场写入持久层**（数字+时刻+口径），对话文本不是存储

## 负结论与"不存在"的复核

- 一切负结论（0 / 不在 / 找不到 / 空）必须复核产生机制：工作目录漂移、命令返回码、stderr 被吞、路径错误。**取证命令一律不带 `2>/dev/null`**。
- 查「最新一条」先确认排序列类型——UUID 主键 `ORDER BY id DESC` = 随机抽样，一律按时间戳排序（且注意时间戳列的 NULL 与时区）。
- 判「记录不存在」前：**分页拉到空页**（服务端无视 limit 参数、固定每页 N 条是常态）；从截图/口头抄来的 ID 逐字符比对再进查询。
- 断言「全零/整缺/不可回溯」前：看的是完整数据域吗？全分页、全时间窗、完整响应体——不是前 N 个字符、不是第 1 页、不是首屏。
- 带会话态的探测（切主体/切账户后查询）结论必须隔离复跑验证；"本该不同的结果完全相同"是**探测失效**的信号，不是服务端变了。
- 中文/编码显示异常：先怀疑终端/管道编码（Windows GBK），用码点验数据本身。

## 单测的边界

- fake/mock session 的单测**不执行真 SQL**——语法错、类型错拦不住。新增/改动手写 SQL 必须真库冒烟一把。
- 单测喂不出"衍生指标永远取默认值"这类逻辑矛盾（过滤条件把要算的状态滤掉了）——聚合查询里派生指标先问"where 是不是已经把它滤没了"。
- 哨兵/审计/告警代码的**异常分支**（0/None/空列表/源不可达）必须有测试喂过——哨兵自己在该报警的场景先崩 = 没有哨兵。
- 测试全绿 + 生产崩的另一种来源：模块级注解引用了函数体内才 import 的类型（启动即 NameError）——改完必须实测启动，不能只看语法。

## 时区与时间窗

- 跨时区时间过滤一律带完整时区的 ISO 字符串；纯日期字符串会被当 UTC 解析，月初/月末差出 8 小时。
- 容器日志、同步记录、云服务时间戳常是 UTC——人工排查换算本地时区后再对表；判断"避峰窗口"同样先换算。
- 排查"今天数据缺"前先确认该源的**结算延迟口径**（T+1/T+N 是设计，不是丢数）。
- 平台数据"分批到位"（当天缺、次日分批补齐）是常见家族——判别法看班次历史：每班仍有行进账 = 到位中（良性）vs 连续整班零/失败 = 升级。
