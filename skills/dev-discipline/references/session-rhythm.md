# 开工收尾节奏与知识沉淀

背景：长期项目跨数十个会话、多条专线（开发线/审查线/修复线）并行推进，靠的不是会话记忆力，而是**文档体系 + 记忆 + 台账**三件套。历史教训：对话里说过的基线数字压缩后即失；memory 里挂着的待办早被别的会话修掉；完成的任务没纠正旧索引，留下僵尸结论误导后来者。文档是给下一个会话（包括未来的自己）写的，不是给当前对话写的。

## 开工三读

1. **项目 CLAUDE.md**：环境事实（服务器、部署方式、容器、禁忌操作）+ 项目铁律。环境事实不要用教训重新换一遍——前人已经用事故换好了。
2. **教训/复盘清单**（如有 docs/09 这类）：动手前过一遍与本任务相关的条目 + 文末快速自检。
3. **最新交接文档 + 台账尾**：交接文档是遗留问题总入口（当前有效的取代旧的）；部署/DDL/操作台账的尾部告诉你别的会话最近干了什么。

开工还要做的两个校准：

- **多会话认知作废重核**：别的会话部署过/改过 = 我对"现状"的既有认知全部重核（见 production-safety.md 多会话协调）。
- **memory/文档会过时**：记录里的"待办/故障"可能已被修掉，`问题可能已被上一轮修掉`——先查代码/数据现状。反过来，引用旧交接待办前先查现值（镜像可能已回填）。

## 会话中的记录纪律

- **基线落盘**：供后续对比的观测基线（性能快照、行数、金额）当场写入持久层——数字 + 时刻 + 口径三要素齐全。对话文本不是存储；"我说过"≠"我存了"。
- **口径/定案即时入档**：用户拍板的口径决策（如"以 X 为准""这类不算消耗"）当场落到权威文档并注明日期与原话，后续对数以此为准。
- **临时探针脚本集中管理**（如 `_tmp/` 或 `_audit_tmp/` 目录）：写完先 `ast.parse`/语法预检再上生产执行；每段独立 try/except + rollback 防事务串扰；探针里不打印明文敏感字段。
- **取证姿势**：SSH/容器执行用 stdin 管道模式传脚本；多层 shell（bash→ssh→psql）间语义会漂移（虚拟路径、变量插值、引号嵌套），敏感值搬运用显式临时文件 + 用完即删，全程值不进命令行参数。

## 收尾清单（任务完成 ≠ 会话可以结束）

1. **更新进度权威文档**：每个项目应该有一个"进度总览"权威快照，收尾时滚动增量块（⚡增量速览 + 链接到详细交接）。
2. **写/更新交接文档**：编号递增，新文档声明"取代旧文档"，并在旧文档处留下指路。按三档组织最有效：
   - **一档：我方待批执行包**（用户说一声即办，可打包；附证据与量级）
   - **二档：用户/业务侧动作**（系统侧已完成或等待输入）
   - **三档：观察项/挂账**（不阻塞，附判读口径：什么情况算良性、什么情况升级）
3. **纠正旧结论**：完成一个任务后，同步修正所有引用旧结论的文档/索引/记忆——不留僵尸表述。被翻案的结论明确写"XX 作废，新结论是 YY"。
4. **更新记忆**：会话级记忆按"全案闭环/待拍板/新坑"压缩，相对日期转绝对日期。
5. **留验证钩子**：T+1 类、跨班次类改动写清"明早/下一班核什么、预期什么值、什么算失败"。
6. **新教训入清单**：本次会话犯的错/差点犯的错，提炼成条目（犯过的错 → 真相/根因 → 防再犯规则）入项目教训清单，**只增不删**；编号避让并行会话已占用的段。

## 交接文档的有效格式（实证有效）

- 开头一段"现状一段话"：最新部署、健康度摘要（几绿几黄几红、红项是否全部可归因）、关键资源水位。
- **结论挂一手证据**：每个定案附探针脚本名/命令/数字，后来者可复现。
- 禁令与安全关键单独成节（新会话必须遵守的浓缩版，全文指向 CLAUDE.md）。
- 环境速查表：连接方式、容器名、启动顺序、审计明细查看姿势。
- 上一版交接的闭环对照表：旧待办 → 现状态，让接力者不用翻历史。

## 沟通风格（与用户协作的实证经验）

- 汇报先结论后证据；数字精确到分；"分毫不差"要有对账输出支撑。
- 坏消息直说：做错了什么、影响多大、怎么补救，不淡化。事故的第一优先级是坦白与止损，不是解释。
- 用户拿截图/口头数字反问时，通常意味着我方的查询域有盲区——先复查自己（分页/窗口/会话态），再怀疑源端。
- 待用户拍板的事项收集成一档清单批量问，别零碎打断；提问时附上推荐选项和依据。
- 敏感值（密码/cookie/token/手机号）永不进对话；输出前脱敏或只报形态（"11 位手机号形态"）。
